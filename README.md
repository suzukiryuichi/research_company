# Company Note

就職活動に向けて企業情報を整理し、同じ視点で比較できる日本語のWebアプリです。

## 起動

Node.js 22.13 以上（最新LTS推奨）が必要です。PDF読取ライブラリを導入して起動します。

```sh
cd /workspace/research_company
npm ci --ignore-scripts
npm start
```

ポートは標準で `3000` です。`PORT=3001 npm start` で変更できます。

Windowsでは、ZIPを展開した後に `start-windows.bat` をダブルクリックすると、初回に必要なライブラリを自動導入して起動できます。初回の導入にはインターネット接続が必要です。開いたウィンドウは利用中そのままにしてください。`http://localhost:3000` をブラウザで開きます。終了するときは `Ctrl + C` です。

### 以前のZIPから更新する場合

現在のノートを画面から書き出してバックアップし、古いサーバーを `Ctrl + C` で停止してください。新しいZIPを別フォルダに展開して、そちらから起動します。引き続き同じブラウザの `http://localhost:3000` で使えば、従来のブラウザ内データを読み込めます。必要ならバックアップを読み込んでください。

## 機能

- 企業情報の追加・編集・削除（業界、職種、所在地、採用サイト、応募締切、選考ステータス）
- 5つの研究メモ（事業、強み、社風、志望動機、面接で聞きたいこと）
- キーワード検索、業界・ステータスでの絞り込み、並べ替え
- お気に入りと最大3社の比較表
- ブラウザ内の自動保存、JSONバックアップの書き出し・読み込み
- スマートフォン対応
- Qwen（研究室API）による公式サイトの整理、またはOpenAI APIのWeb検索による企業研究
- AI下書きの出典・調査日時の保存、選択した項目のみ取り込み

初回には**架空の企業3社のサンプル**を表示します。サンプルは編集・削除できます。

## データの保存

企業ノートは利用中のブラウザの `localStorage` に保存されます。AI調査の実行時、Qwenモードでは企業名・公式URL・取得した公開ページ本文を研究室APIへ、OpenAIモードでは企業名と任意の公式URLをOpenAIへ送信します。既存の研究メモや志望動機は送信しません。ブラウザ・端末・アクセス元のホストやポートが異なると保存領域も異なります。ブラウザデータの消去や環境変更に備え、サイドバーから定期的にJSONを書き出してください。

バックアップの読み込みは現在の企業情報を**全件置き換え**ます。実行前に確認画面が表示されます。保存済みデータが壊れている場合は自動上書きせず、バックアップから復元できます。

アカウント・クラウド同期は含まれません。サーバーは自分のPC専用に `127.0.0.1` で待ち受けます。

## Qwen・研究室APIの設定（Windows）

今回の接続先・モデルは `.env.example` に設定済みです。モデルサーバーがOpenAI互換の **Chat Completions API** に対応していることを前提にしています。実際に呼び出す先は `https://haisoft.comp.ae.keio.ac.jp/v1/chat/completions` です。

1. 新しいZIPを展開します。既に起動しているサーバーは `Ctrl + C` で停止してください。
2. アプリのフォルダでPowerShellを開き、設定ファイルを作成します。既に `.env` がある場合は上書きせず、メモ帳で以下の設定に変更してください。

```powershell
Copy-Item .env.example .env
notepad .env
```

3. 内容が次のようになっていることを確認し、`RESEARCH_API_KEY=` の後ろに**研究室から発行されたAPIキー**を入力して保存します。OpenAIのAPIキーは使いません。

```dotenv
RESEARCH_PROVIDER=qwen
RESEARCH_BASE_URL=https://haisoft.comp.ae.keio.ac.jp/v1
RESEARCH_MODEL=qwen3.8-27b
RESEARCH_API_KEY=
```

4. `start-windows.bat` をダブルクリックするか、PowerShellで `npm start` を実行します。
5. 同じブラウザの `http://localhost:3000` を開きます。「AIで企業研究」で**企業名と公開公式サイトのURLの両方**を入力します。

Qwenモードでは、標準24件（12・24・40件から選択）のページ取得を試み、最大3階層まで巡回します。会社・理念、事業・製品、採用・働き方、IR・経営などに取得機会を分け、一分野のリンクだけで枠を使い切らないようにしています。サイトマップ本体と最大2つの子サイトマップからも候補を発見します。採用・IRが別ドメインの場合は、検索画面の「追加URL」に公式URLを1行1件、最大4件入力してください。指定ドメインとそのサブドメインの範囲で巡回します。ページ数上限は失敗・重複転送を含む取得試行数です。サイトマップの取得は別に数えます。キーは研究室のモデルAPIだけに送り、企業サイトには送りません。Qwenの学習済み知識だけで出典を作ることはしません。Web全体の検索や企業サイトの発見は行わないため、公式URLが必要です。

取得には公開IPv4のHTTP/HTTPSページを使います。学内・ローカルアドレスへの取得は行いません。文字を含むPDFも読取対象です（最大12MB・先頭20ページ・本文24,000文字）。画像だけのPDFのOCR、ログイン必須ページ、JavaScript実行が必要なページには対応していません。HTMLは1ページ最大12,000文字を読みます。ページが取得できない場合は、別の会社概要・事業ページのURLを指定してください。取得した一部ページが失敗した場合は、成功したページだけを使い、その旨を結果に表示します。収集後は最大4資料・本文合計24,000文字を目安に分けてQwenへ送り、複数バッチなら最後に出典IDを保持して統合します。単一バッチなら1回、複数バッチならバッチ数+1回のAPI呼び出しになります。ページ取得とモデル応答を合わせ最大15分で中断します。

APIキーは `.env` にだけ保存してください。キーをチャットやGitHub、配布ZIPに含めないでください。`.env` を変更した場合はサーバーを再起動してください。研究室APIの課金・利用条件は管理者に確認してください。VPNや学内接続が必要な運用の場合は、その接続も必要です。

キーのないこのクラウド環境から研究室APIへの実接続は通信経路で403となり、確認できていません。テスト用のOpenAI互換応答で接続処理・出典保存・既存ノート保持を検証しています。401/403は認証・利用権限、404はAPI形式やbase URL、応答形式エラーはモデルがJSONを返せているかを確認してください。

Qwenモードで `OPENAI_API_KEY` を研究室の認証に自動流用することはありません。`RESEARCH_API_KEY` を設定してください。

### 見落としを確認する方法

結果と保存済みノートに、最終調査の取得件数、分野別件数、全取得ページ、失敗URL・理由、未取得候補数を表示します。これらはバックアップにも保存されます。「未確認」の分野には採用トップ・IRトップ等のURLを追加し、40件を選んで調べ直してください。上限・深さ・本文長の制限があり、サイトマップ未掲載、画像資料、アクセス制限のあるページもあります。件数は網羅率ではなく、企業サイト全体を読み切った保証でもありません。

このバージョンでは記事検索や競合情報の外部Web検索を追加していません。追加URLには対象企業の公式サイトを指定してください。

## OpenAIを利用する場合（任意）

`.env` に `RESEARCH_PROVIDER=openai` と `RESEARCH_MODEL=gpt-4.1` を設定してください。`RESEARCH_API_KEY` はOpenAIのキーに変更します。Qwen用base URLはこのモードでは使用しません。

手入力の機能はAPIキーなしで使えます。AI調査にはOpenAI APIキーと、APIの利用残高・利用権限が必要です。**ChatGPTの有料プランとは別の従量課金**です。

1. [OpenAIの管理画面](https://platform.openai.com/api-keys)でAPIキーを作成します。必要に応じてAPIの支払い・利用上限を設定してください。
2. `package.json` があるアプリのフォルダでPowerShellを開きます。起動済みなら `Ctrl + C` でサーバーを止めます。
3. 次のコマンドで設定ファイルを作成して開きます。既に `.env` がある場合はコピーを省略し、編集してください。

```powershell
Copy-Item .env.example .env
notepad .env
```

4. メモ帳で `RESEARCH_API_KEY=` の右側に自分のAPIキーを入力して保存します。キーをチャットに貼ったり、画面共有したりする必要はありません。
5. PowerShellで起動します。

```powershell
npm start
```

6. ブラウザで `http://localhost:3000` を開き直します。

`.env` はサーバー起動時に読み込まれます。変更したら必ずサーバーを再起動してください。APIキーはブラウザに配信されず、Gitの対象からも除外しています。自分でZIPを作る場合も `.env` を含めないでください。既に `RESEARCH_API_KEY` または `OPENAI_API_KEY` を環境変数に設定している場合はそれも利用できます（`RESEARCH_API_KEY` を優先）。

### AI調査結果の取り込み

1. 「AIで企業研究」を押して、企業の正式名称と任意の公式サイトURLを入力します。既存ノートの編集画面の「AIで調べる」からも利用できます。
2. 「Webで調べる」で調査します。OpenAIモードはWeb検索と構造化のためにResponses APIを2回呼びます。Qwenモードは取得資料を複数回に分けて研究室のChat Completions APIに送り、最後に結果を統合します。ページ数が増えると時間とモデルサーバーの利用量も増えます。自動的な再検索・バックグラウンド実行はしません。
3. 出典付きの下書きを確認し、取り込む項目を選びます。記入済みの項目は初期選択されません。選んだ項目だけ編集画面に反映され、この段階では保存しません。
4. 必要に応じて編集し、「ノートを保存」を押します。出典と調査日時もバックアップに含まれます。

OpenAIモードには企業の公式ページ・採用・IR情報を優先するよう指示していますが、必ず公式情報が見つかるとは限りません。Qwenモードは入力された公式サイトが対象企業のものか、自分で確認してください。出典付きの結果がない場合は取り込みを行いません。志望動機、職種、選考状況、応募締切は自動入力しません。面接質問はAIの提案です。古い情報・同名企業・誤りの可能性があるため、結果は出典と照合してください。手動で書き換えた項目のAI引用は外します。

調査の中断時にも、OpenAIで既に実行した処理に料金がかかる場合があります。エラー時には、キー、API残高、モデル・Web検索の利用権限、通信状態を確認してください。標準モデルは `gpt-4.1` です。対応モデルを変更する場合は `.env` の `RESEARCH_MODEL` に指定します。Responses APIのWeb検索とJSON Schema出力に対応したモデルが必要です。

## 検証

```sh
npm run check
npm test
```

HTTPサーバーはNode.jsの標準ライブラリを使い、PDF抽出には固定バージョンのpdfjs-distを使います。Node.jsのテストランナーでデータ処理、AI応答の検証、出典の保持、HTTPエンドポイントを検証します。テストでOpenAIの有料APIは呼び出しません。
